# GraphRAG for millenium: findings and proposed integration

## Context
The user asked what adding GraphRAG to this project would look like. Today retrieval is dense search (6 query
variants, RRF) + BM25 + cross-encoder + scene summaries + entity cards/matrix (`app/entities.py`, 4,043 entities,
3,255 edges, each edge pointing to the passage IDs that state it). Those cards are already a knowledge graph that is
only used as a lookup table: nothing walks it. The largest open failure group (data/tuning/LOG.md, set3: 8 of 12
failures) is passages that name their subject only as "my father", "the patient" or "him", with the name given
earlier; dense rank 100–2000, cross-encoder −7…−11. Global questions ("Who is Mikael Blomkvist?", "What is Salander
known for?") are a second weak group.

## Options researched
| Option | Fit | Cost here |
|---|---|---|
| Microsoft GraphRAG (local/global/DRIFT search, community reports) | Best for global "who is / what is" questions | Separate index + query engine; needs reliable JSON from Ollama (docs warn of malformed JSON); community reports add many LLM calls on top of the ~2.8 h extraction; bypasses Langfuse tracing, pinned prompts and the calibrated admission rules |
| LightRAG (entity + relation keys, dual-level retrieval) | Entity lookups; runs with Ollama, no strict JSON | Own storage and retrieval loop; same replacement problem; re-extracts what `entities.jsonl` already holds |
| HippoRAG 2 (entity–passage graph + Personalized PageRank) | Multi-hop / associative recall; cheapest indexing of the three | One third-party paper reports weak NarrativeQA results (PPR damping fades links across a long novel) |
| **In-house graph on the existing entity cards** (recommended) | Same idea as HippoRAG; fits the pipeline's "add hits in front only when they beat every fused candidate" pattern | No new service; scipy is already installed (sentence-transformers needs it); index cost ≈ 0 because the cards exist |

Frameworks would replace the pipeline instead of adding one path, so they could not be measured under the
"one change, zero regressions" rules in IMPROVEMENTS.md. Recommendation: build the graph path in-house, and try
Microsoft GraphRAG only as an offline comparison later if global questions stay weak.

## Proposed integration (opt-in `entity_graph`, off until validated)
1. **Graph build** (`app/entities.py`, new `build_entity_graph`): nodes = entity cards + passages; edges =
   entity–passage (card `members`), entity–entity (card `edges`, weighted by `count`), passage–next-passage within a
   section. Sparse matrix saved next to the cards file, identity hashed the way `entity_cards_path` is. No LLM calls.
2. **Coreference so the graph reaches pronoun passages** (the part that addresses set3): re-run entity extraction with
   the carried text before the window (same approach as `scene_carry_chars` in `app/scenes.py`, prompt
   `entity_extraction_carry_system`), so "my father" in a window becomes a mention of Gottfried Salander. ~2.8 h with
   gemma4:26b, cached in `ENTITY_CACHE` under a new prompt hash.
3. **Query** (`app/pipeline.py`, new `_entity_graph_hits` next to `_entity_matrix_hits`): seeds = question entities
   (`_entity_anchors`, name variants, `_complete_names`) + top reranked passages; Personalized PageRank
   (scipy sparse, ~20 iterations, damping configurable); top `entity_graph_pool` passages not already in evidence are
   reranked against the question, and up to `entity_graph_max_hits` are added after the usual evidence only when they
   beat every fused candidate and `low_confidence_score` (same bar as the wider pool). Timing in `timings`, a Langfuse
   span like the other paths.
4. **Config** (`app/resolved_config.py`): `entity_graph` (bool), `entity_graph_damping`, `entity_graph_pool`,
   `entity_graph_max_hits`, validated like `entity_matrix_*` and added to the identity field set.
5. **Later, only if global questions still fail:** per-person profile cards (one LLM summary per entity with ≥ N
   mentions, GraphRAG's "community report" idea at entity level) indexed as a third Qdrant collection.

## Verification
- Offline first (per the tuning rules): replay recorded queries for set3 targets, measure the gold passage's PPR rank
  and rerank score, and the blast radius (how many QA.csv / Additional Questions items get different evidence).
- Unit tests in `tests/` for the graph build (edges from members, section links) and PPR seeding.
- Then full QA.csv, Additional Questions and set3 runs in the `millenium-tuning` container, per item against the
  current defaults, repeated; zero drops required; log the round in IMPROVEMENTS.md. One Ollama model at a time.

## Outcome (2026-10-18)
Implemented as planned, with stage 2 extracting events between people (carried context) instead of re-extracting the
cards. Rejected on the datasets: passage hits set3 0.477 → 0.432; event lines 7 up / 16 down over 94 items. Code kept
off by default; the `_entity_anchors` fix it uncovered is on. Details in IMPROVEMENTS.md (2026-10-18).
