# v2.16 maintenance cleanup plan

Date: 2026-11-25
Status: Implementation authorized and in progress; code cleanup completed, final live comparison and completion audit underway.

## Objective and agreed scope

Retain the current default pipeline, named **v2.16**, with its local Ollama and OpenAI provider options. Remove historical pipeline execution code and logic that is neither used by v2.16 nor shared with retained functionality.

Older versions may become completely unsupported. Reproducing their execution is not required; Git history will provide recovery through focused, reviewable commits.

Preserve existing experiment results, metrics, manifests, reports, Langfuse integration, recorded traces, and trace links. Do not delete or relabel historical Langfuse objects. Rescoring recorded answers is distinct from rerunning historical pipelines and is not automatically in removal scope.

The audit was read-only. No tests or experiments were run as part of preparing this plan. Candidates marked for caller checks require confirmation during implementation; source inspection alone does not establish that every candidate is safe to delete.

## Retained dependency path

API / experiment CLI → resolver → v2.16 → agent runner → retrieval tools and model provider → results, evaluation, and Langfuse.

| Area | Retained behavior |
| --- | --- |
| Pipeline identity | v2.16, selected by default |
| Local agent | Ollama; catalog default qwen3.6:35b |
| OpenAI agent | Existing provider adapter and reasoning-effort options |
| Local options | Model, thinking, and context-length overrides |
| Retrieval options | Automatic scene search, scene candidate count, premise early-stop override |
| Query transformations | Expansion, HyDE, grammar correction, and supported transformation settings |
| Agent behavior | Current pre-checks, submission verification, search progress, synthesis, reranking, conversation handoff |
| Shared infrastructure | Corpus profiles, indexing, scenes, entity cards, caches, streaming, rate limits |
| Experiments | Current runner, datasets, evaluator selection, metrics, artifacts, Langfuse uploads |
| Historical records | Existing results, scores, manifests, trace links, reports |

The frontend currently explicitly requests v2.16 with OpenAI and high reasoning effort in `frontends/millennium/server.js`. The catalog defaults to local Ollama. Preserve both behaviors.

Selecting OpenAI changes the query agent. Shared local model work, such as query transformations, remains part of the current implementation.

## Dependency audit and removal list

### 1. Catalog and resolver

Files: `pipelines.md`, `pipelines.sha256`, `app/pipeline_catalog.py`, `app/pipeline_resolver.py`.

Remove:

- Every catalog block except v2.16: v1, v2, and v2.2 through v2.15.
- Corresponding historical release-checksum entries.
- The fixed-engine alias that resolves to v1.
- Fixed-engine schema requirements, including seven managed RAG prompts.
- Draft-pipeline resolution and draft-only prompt-label support.
- Historical instruction-fingerprint constants and compatibility exceptions: original v2 literal compatibility, v2.2/v2.3 provider-adapter compatibility, older scene-probe/trace compatibility, draft scoped-instruction compatibility, and historical handoff compatibility.
- `_legacy_v2_instructions_unchanged()` and its exclusive dependencies.
- Version-specific automatic scene candidate defaults for v2.6–v2.10.
- Historical pinned-index handling used solely by removed entries, after confirming it is unnecessary for v2.16.

Keep default and explicit v2.16 selection, provider/settings validation, derived-run identities, corpus/profile/prompt/model/index identities, tool-list validation, and meaningful instruction protection.

Requests for removed versions must fail explicitly, never silently execute v2.16.

### 2. Execution and API branches

Files: `app/pipeline_runner.py`, `app/main.py`, `app/experiments.py`.

Remove:

- Fixed-pipeline dispatch and imports of `run_pipeline`.
- v2.13/v2.14 draft prompt selection and v2.14 graph-search enablement.
- Version-specific prompt routing for v2.7–v2.9.
- Managed fixed-pipeline prompt loading from interactive requests and experiments.
- Request/CLI fields used only for fixed or draft behavior, particularly `prompt_label`.

Preserve corpus-specific agent prompts for non-Millennium corpora, streaming, citations, metadata, queueing, retries, item selection, evaluators, and upload verification. Preserve result fields consumed by historical record readers or the frontend. Avoid unrelated API renaming or response redesign.

### 3. Original fixed pipeline and shared helpers

File: `app/pipeline.py`.

Remove `run_pipeline()` after removing its callers.

Candidate helper removals, subject to final caller checks:

- `_translate()`, `_english_share()`, and exclusive translation dependencies.
- `_rrf()`.
- Fixed-pipeline entity-name and entity-matrix retrieval.
- Fixed-pipeline graph retrieval and graph-fact augmentation.
- Fixed-pipeline scene/context augmentation.
- Evidence formatting and answer orchestration exclusive to `run_pipeline()`.
- Exclusive wide-search, low-confidence, baseline-mode, and passage-augmentation helpers.

Do not delete the module wholesale. The current agent imports embedding, cached vector queries, reranking, keyword search/indexing, query transformations, entity-card/anchor helpers, name pairs, scene-moment retrieval, passage ordering, and Qdrant access from it.

Initially retain shared helpers in place. If extraction into better-named modules is useful, perform it in a separate mechanical commit so moves do not obscure deletions.

### 4. Historical agent variants

File: `app/agent.py`.

Remove:

- `ENTITY_CARD_DRAFT_PROMPT`, `STORY_GRAPH_DRAFT_PROMPT`, and `draft_system_prompt()`.
- Experimental graph-search implementation, tool specification, dispatch registration, and enablement argument.
- Exclusive graph helper imports after caller checks.
- The pre-v2.16 evidence-digest forced-answer path: `FORCED_ANSWER_PROMPT`, `_evidence_digest()`, and old forced-answer message construction.
- The disabled conversation-handoff branch: v2.16 enables handoff and the resolver exposes no override for it.

Further candidates, after migrating direct callers/tests: disabled progress-control and disabled query-aware-reranking branches. Both are enabled in v2.16 and are not current resolver overrides.

Keep `agent_final_handoff.py`, conversation compaction, entity/connection tools, provider adapters, usage/cost tracking, verification, synthesis, abstention handling, and coverage checks.

Keep premise probing and direct premise resolution: early stopping defaults to false but remains an exposed option. Keep automatic scene probing and its disabled option. A false default alone does not make functionality stale.

### 5. Configuration and prompts

Files: `app/resolved_config.py`, `app/prompt_templates.py`, `app/prompt_assets.py`.

After consumer checks, remove fixed-only configuration fields and their validation, environment parsing, serialization, and documentation. Likely groups: wide retrieval, low-confidence fallback, RRF, entity-matrix augmentation, fixed graph augmentation, and fixed answer-generation toggles.

Remove fixed-answer and translation templates only when no retained consumer uses them. Remove managed RAG prompt-loading/reconciliation branches exclusive to the fixed engine.

Keep transformation prompts used by `expand_query`, scene-moment/generation prompts, synthesis prompts, evaluator definitions, managed judges, corpus-specific evaluator configuration, model identities, and index/chunking settings.

Do not delete `prompt_assets.py`: it also supports retained evaluators.

### 6. Superseded experiment entry point

Propose deleting `app/run_agentic_experiment.py` after checking callers and operating instructions. Its documentation describes a temporary bridge until the durable experiment runner supports pipeline selection; `app.experiments` now supports that capability.

Replace references with the supported runner.

Keep by default `app/rescore_existing_experiment.py`, `app/rescore_separate_experiment.py`, experiment storage, and historical result-reading code. Rescoring recorded answers is not historical pipeline execution.

### 7. Tests

Remove or rewrite coverage requiring historical catalog entries, fixed-engine execution, legacy aliases, draft prompts/graph variants, historical fingerprint exceptions, and fixed-only settings/retrieval paths.

Affected files include `tests/test_pipelines.py`, `tests/test_workflow.py`, `tests/test_answer_settings.py`, and portions of `tests/test_agent.py` and `tests/test_api.py`.

Retain shared coverage within those files, including transformation tests. Do not delete a test file solely because most of it covers removed functionality.

### 8. Documentation and dependencies

Update README, technical guide, CLI/provider examples, fingerprint explanations, and current pipeline diagrams. Every current pipeline diagram must visibly identify v2.16, aligned with the catalog.

Update the v2.4 example in `AGENTS.md` while preserving required Git mount and safe-directory instructions.

Preserve historical experiment reports and recorded data. Historical version mentions in those records are expected and must not be relabeled as v2.16.

Unused frontend components/packages are secondary candidates requiring an import audit. The initial audit does not justify particular package deletions.

## Fingerprint strategy

| Protection | Current behavior | Planned treatment |
| --- | --- | --- |
| Catalog release hash | Hashes pipeline definition | Retain v2.16 protection; remove historical entries |
| Instruction fingerprint | Hashes every string literal in agent.py and prompt_templates.py | Replace overly broad coverage with an explicit current instruction manifest |
| Handoff fingerprint | Hashes agent_final_handoff.py bytes | Keep; avoid unnecessary changes to that file |
| Source fingerprint | Records source files and Git revision | Keep; expected to change during cleanup |
| Run/cache identities | Include pipeline/configuration identities | Preserve isolation and verify incompatible answers cannot be reused |

The current instruction fingerprint includes unused draft prompts, obsolete branches, and non-instruction strings. Deleting unused code can therefore invalidate v2.16 without changing model-visible behavior.

Migration steps:

1. Capture current prompt messages, tool specifications, defaults, and handoff behavior in deterministic fixtures.
2. Define an explicit instruction manifest covering retained model-visible instructions and tool schemas.
3. Verify retained messages and schemas match the baseline.
4. Replace broad literal scanning with the new fingerprint method.
5. Update v2.16's instruction fingerprint and catalog checksum in a dedicated commit.
6. Document the protection-format migration and unchanged intended pipeline behavior.

Fingerprints will change while the pipeline name remains v2.16. New source/run identities must record that accurately. Historical manifests remain untouched.

Do not disable validation, accept arbitrary hashes, or add another permanent compatibility exception to make deletions pass.

## Commit sequence

Each commit must leave the supported path working and include corresponding test updates. Split large commits by dependency chain as needed.

| Commit | Scope | Verification gate |
| --- | --- | --- |
| 1. Capture v2.16 contract | Defaults, both providers, tools, prompts, handoff, metadata baseline coverage | Baseline passes before deletion |
| 2. Narrow catalog/resolution | Only v2.16; remove resolver exceptions, aliases, draft selection | Default/explicit selection passes; removed versions fail clearly |
| 3. Migrate instruction protection | Current instruction manifest and deliberate hash updates | Prompt/tool fixtures unchanged; tampering fails |
| 4. Remove historical agent variants | Draft prompts, graph tool, old forced answer, proven obsolete branches | Tools, verification, synthesis, budget handoff pass |
| 5. Remove fixed execution | Dispatch, API/experiment branches, run_pipeline orchestration | API, streaming, current runner pass |
| 6. Remove orphan helpers/settings | Fixed-only helpers, configuration, templates, imports | Shared retrieval/transformation/indexing passes |
| 7. Remove superseded runner | Temporary bridge and references | Current experiment entry point and record readers pass |
| 8. Documentation/dependencies | Guides, diagrams, proven unused assets/packages | Frontend tests/build and reference checks pass |

Do not mix helper reorganization with deletion unnecessarily. Git history provides recovery; a duplicate runtime-code archive is unnecessary.
